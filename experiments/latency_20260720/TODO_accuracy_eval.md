## 2. 왜 CARLA인가

CARLA는 시뮬레이터가 모든 액터의 3D 바운딩박스·클래스·가시성(occlusion)을 알고
있으므로, **수작업 라벨링 없이 정답데이터를 자동 생성**할 수 있다. 실도로 영상은
직접 라벨링해야 하므로 비용이 크고, 라벨 품질 자체가 논쟁거리가 된다.

## 3. 수행 계획

### 3-1. 정답데이터 생성
- CARLA 서버 실행 (`Downloads\CARLA_0.9.16.zip` 확인됨 — 실행 가능 여부부터 점검)
- 동기 모드(`fixed_delta_seconds=0.05`)로 시나리오 주행
- 프레임마다 다음을 동시 저장:
  - RGB 이미지 (sender와 동일하게 CAMERA_WIDTH×CAMERA_HEIGHT)
  - 각 액터의 3D bbox → 카메라 투영 → 2D bbox (COCO 클래스 매핑: person/car/truck/bus)
  - 가시성 필터: depth 카메라로 occlusion 판정, 화면 밖·완전 가림 객체 제외
  - 최소 bbox 픽셀 면적 임계값 적용 (너무 작은 객체는 평가 대상에서 제외)
- 출력 포맷: YOLO 표준 라벨 (`class cx cy w h`, 정규화 좌표)

### 3-2. 평가
- `ultralytics`의 `model.val()` 또는 자체 평가 스크립트로 산출
- 지표: **mAP@0.5, mAP@0.5:0.95, precision, recall, F1** (클래스별 + 전체)
- IoU 임계값 0.5 기준 TP/FP/FN 혼동행렬
- 측정 조건 명시: yolov8n.pt / imgsz=640 / conf=0.35 (지연측정과 동일 조건 유지)

### 3-3. 시나리오 다양성
단일 시나리오 결과는 일반화가 안 되므로 최소 다음을 분리 측정:
- 주간 / 야간
- 맑음 / 우천
- 직선 고속주행 / 교차로
- 근거리(<20 m) / 원거리(>40 m) 객체

### 3-4. 한계 명시 (보고서에 반드시 포함)
- CARLA는 시뮬레이션이므로 실도로 도메인과 갭이 있다(sim-to-real gap).
- 따라서 산출된 mAP는 "시뮬레이션 환경에서의 검출 성능"으로 한정해 서술하고,
  실도로 성능이라고 주장하지 않는다.
- 여력이 되면 직접 촬영한 실도로 영상 일부를 수동 라벨링해 보조 검증한다.
